Project objectives

Encrypt on the FPGA

Your data goes over USB to the board, through the selected core, and back. Every block is re-computed in the browser and compared.

Result

Decrypt

ciphertext + the same key → the original message

Decryption runs in the browser: the FPGA in this project is encrypt-only (hardware decryption is future work). Try a wrong key: you get garbage, which is the whole point.

Inside AES-128

Step through the ten rounds the hardware executes. The intermediate states come from the browser model; the final ciphertext is checked against the FPGA.

Key schedule

computed on the fly in hardware: 4 S-boxes, 128 flip-flops

Hardware benchmark

The FPGA streams blocks through a core back to back and counts clock cycles itself, so the USB link plays no part in the figure. The XOR of every ciphertext is checked against WebCrypto.

Throughput

Gbps, log scale · measured at 100 MHz on the board

Constant-time check

timing attacks need the latency to depend on the data

Encrypts random blocks with random keys on every core and records the latency the hardware counted.

Image encryption lab

The reference paper's demo. Every pixel block is encrypted by the FPGA. ECB leaks the picture's structure; CTR, built from the same core, does not.

NIST FIPS-197 verification on hardware

Published known-answer vectors plus random keys and plaintexts, through every core, each answer checked against the browser model.
